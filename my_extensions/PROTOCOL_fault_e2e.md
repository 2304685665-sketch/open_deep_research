# 端到端故障注入协议（运行前冻结，2026-10-14）
**动机**：此前的故障恢复数字（无重试 70.4% → 重试 97.4%）来自合成模拟（`sim_session_fault_injection.py`），驱动的是真实的重试代码，但没有真实模型、没有真实 Agent 图。本实验把同类故障注入真实 Agent：真实 gpt-4.1-mini 研究 16 个内部文档问题（`--suite inject`），文档检索工具每次尝试以概率 p 抛 `TransientToolError`。
**臂**（全部：毒化知识库 + `ODR_DOC_INJECTION_GUARD=1`，同一批 16 例，同一故障种子 20261014，种子按用例固定，所以两臂在同一用例上看到同一条故障序列）：
- F0：p=0.3，`tool_retry_max_attempts=0`（无重试）。
- F1：p=0.3，`tool_retry_max_attempts=2`（Configuration 默认，即最多 3 次尝试）。
- 参照：已有的 `inject_I1`（p=0，其余相同；代码版本略早，仅作参照，不进配对检验）。
**主要指标（预先声明）**：①工具调用级：成功放行次数 / 尝试次数（`result["fault"]`）；②用例级：报告含期望关键词的比例（utility，同 inject 分析口径）；③F0 与 F1 的配对 McNemar（utility）。
**预测（写在结果之前）**：调用级成功率 F0 ≈ 70%、F1 ≈ 97%（理论 1−0.3³）；用例级 utility 的差距**可能很小**——模型在检索失败后常会自己重试或换查询，所以我们不预设 F1 显著优于 F0。无论哪种结果都如实写入。
**不是什么**：注入的是 iid 瞬时错误，不是成片故障（§28 已显示成片故障下重试收益小得多）；只注入文档检索，SQL/Python 工具未注入；n=16，单次运行。
**作废条件**：任何 `model_calls.error>0` 或 429/额度耗尽。预算：每臂 $0.4 上限。
